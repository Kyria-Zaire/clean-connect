## 4. Rollback (si smoke prod échoue)

> **Critères de rollback automatique** :
> - Erreur 5xx > 1 % sur n'importe quelle route critique pendant > 2 min
> - Webhook Stripe en échec > 3 retries consécutifs
> - Capture / transfer Stripe en échec sur le smoke test prod

### 4.1 Rollback code (≤ 5 min)

```bash
# Revenir au tag précédent (à confirmer : v0.1.0-auth-foundation ? ou un tag intermédiaire PRD-002 ?)
ssh deploy@cleanconnect.fr
cd /app/clean-connect
git checkout <tag-precedent>
docker compose -f docker-compose.prod.yml build api
docker compose -f docker-compose.prod.yml up -d api
```

### 4.2 Rollback DB (uniquement si migration en cause)

> Les 9 migrations PRD-003 sont **additives** (pas de `DROP COLUMN` rétroactif). Le code précédent **ignore** les nouvelles colonnes / tables. Donc :
>
> - **Pas besoin** de rollback DB tant que le code précédent ne crash pas au boot.
> - Si crash au boot : appliquer le dump DB pris à l'étape 3.1.

```bash
# Restore en dernier recours uniquement (perte données entre snapshot et rollback)
psql $PROD_DB_URL < /backups/clean-connect-prod-pre-v3.sql
```

### 4.3 Désactivation feature flags (rollback sans rebuild)

Si le problème est **uniquement** côté paiements ou photos, désactiver les features :

```bash
# Sur prod, sans redéploiement complet
docker compose -f docker-compose.prod.yml exec api \
  sh -c 'export FF_PAYMENTS_ENABLED=false && pm2 restart api'
# OU : modifier /etc/clean-connect/.env.prod et redémarrer

# Effet attendu :
# - POST /payments/intent → 503 PAYMENTS_DISABLED
# - POST /webhooks/stripe → 503 PAYMENTS_DISABLED
# - POST /photos/presign → 503 PHOTOS_DISABLED (si FF_PHOTOS_ENABLED=false)
```
